# uploader.jp 魚拓作戦 — システム概要（簡易版）

## 1. 目的

uploader.jp などにある配布ファイルと、その説明・作者・元 URL・利用条件を記録し、複数の保存ノードで長期保全します。

**保全と一般公開は別です。** 保存できたファイルでも、再配布の許可を確認できない場合は一般向けにダウンロード公開しません。

## 2. 基本方針

- ファイル本体とメタデータを分けて管理する。
- ファイルごとに複数の保存先を確保する。全ノードへ全ファイルを複製しない。
- 保存ノードを一般ユーザーへ直接公開しない。
- 公開可否は、権利情報と保存状態を確認して判断する。
- 操作、公開条件の変更、削除対応を記録する。
- 初期版では独自 P2P やファイルの細かな分割は行わない。

## 3. システム構成

| 部分 | 役割 |
|---|---|
| Web UI / API | 検索、管理、申請、公開判定 |
| PostgreSQL | 作品・ファイル・ノード・タスク・履歴の記録 |
| 管理・タスク制御 | 保存先の決定、タスク配布、状態確認 |
| 保存ノード | ファイルを保存し、容量と処理結果を報告 |
| 配信ゲートウェイ | 公開条件を満たしたファイルを中央経由で配信 |

保存ノードは中央サービスへ接続してタスクを受け取り、状態を報告します。保存ノードの保存領域を直接インターネットへ公開しません。

## 4. ファイルの保全

1. 運営が作品情報、元 URL、ファイル情報、利用条件を登録する。
2. 中央サービスが保存対象と保存先ノードを決める。
3. ノードがファイルを保存し、サイズと SHA-256 を計算する。
4. 中央サービスが結果を確認して保存状態を更新する。
5. 保存先が不足した場合は、別の稼働ノードへの再配置を試みる。

取得に失敗した場合は、理由と処理結果を記録します。対象サイトの利用条件や権利関係を確認せずに取得・公開を進めないでください。

## 5. 公開できる条件

一般向けダウンロードは、次の条件をすべて満たす場合に限ります。

```text
public_download_enabled == true
AND redistribution_policy == "allowed"
AND preservation_status == "verified"
AND 正常な保存先が1つ以上ある
```

満たさない場合はファイル本体を配信しません。権利状態が不明、確認中、保留中のファイルは、確認が終わるまで公開しません。

主な状態：

- `preservation_status`：未取得、保存待ち、保存済み、検証済み、劣化、欠損、エラーなど
- `redistribution_policy`：許可、制限、確認中、保留、未確認など
- `public_download_enabled`：管理者が設定する公開フラグ
- `representative`：再配布条件の確認担当者

ファイルを保存できたことは、再配布の許可を意味しません。

## 6. 主なデータ

| データ | 内容 |
|---|---|
| `Artifact` | 作品・配布ページ、作者、元 URL、説明 |
| `FileObject` | ファイル名、サイズ、SHA-256、保存状態、公開条件 |
| `Policy` | 利用条件の根拠、確認メモ、確認者、確認日時 |
| `Node` | ノード種別、状態、容量、利用状況 |
| `Placement` | どのファイルをどのノードに保存しているか |
| `Task` | 保存・検証・削除などの作業。優先度は `0`〜`5` |
| `AuditLog` | 管理操作、判断、処理結果の記録 |

## 7. ノード参加と容量

1. 参加者が公開サイトから申請する。
2. 運営が申請を確認し、承認する。
3. 運営が一回限りの登録トークンと中央 API の URL を渡す。
4. 参加者がノード用の環境変数を設定して起動する。

登録トークンは発行後72時間で失効し、初回登録成功後は再利用できません。トークンは秘密情報として扱います。

参加ノードの主な設定：

- `NODE_NAME`：ノード名
- `NODE_TYPE`：運営から指定された `A` または `B`
- `NODE_CAPACITY_BYTES`：参加者が提供する容量の申告値（バイト）。`0` は参加者側の上限なしを意味しますが、実際のディスク容量は有限です。
- `NODE_UPLOADER_MIN_INTERVAL`：そのノードの agent が uploader.jp へリクエストを送る最低間隔。通常は `30s` を維持します。

運営者用の `.env` と、参加ノード用の `.env` は分けます。管理者の認証情報や中央サービスの秘密鍵を参加者へ渡しません。

## 8. 削除・公開停止

- 申請を受け付けたら記録を作成し、担当者が確認する。
- 公開停止が必要な場合は、中央サービスからの新規配信を停止する。
- 削除が必要な場合は、保存ノードへ削除タスクを発行する。
- 各ノードの処理結果、担当者、理由、時刻を記録する。

公開停止とファイル削除は別の処理として追跡します。オフラインのノードがある場合、削除完了まで時間がかかることがあります。

## 9. 再配布相談・配布代行

公開サイトには2つの窓口があります。

- `/redistribution-support`：手元にファイルがある人向け。ファイルを添付して、運営に権利者への問い合わせと再配布の可否確認を相談できます。
- `/publisher-support`：配布元・権利者向け。ファイルまたは配布元URLを送り、配布先探しや配布対応の代行を相談できます。

添付ファイルは最大100 MiBで、申請確認用に保管します。管理画面の申請詳細から、権限のある担当者が取得できます。アップロード時の自動ウイルス検査は行いません。申請が却下または終了になった場合は添付ファイルを削除します。送信しただけで公開・再配布されることはなく、権利者の許諾や配布条件が確認できない場合は公開しません。

## 10. 初期版の対象外

- 独自の完全分散型 P2P
- 全ファイルの全ノードへの複製
- ファイルの細かな分割・再構成
- 権利状態が不明なファイルの自動公開
- 保存ノードから一般ユーザーへの直接配信

## 11. 運用上の注意

- このシステムは MVP／試験運用版です。可用性や処理時間を保証するものではありません。
- DB、設定、監査ログは定期的にバックアップします。
- 利用規約、プライバシー、免責、削除対応の手順は、実際の運用開始前に確認・更新します。
- 実装の動作とこの概要に違いがある場合は、現行コードと運用ガイドを優先して確認します。
